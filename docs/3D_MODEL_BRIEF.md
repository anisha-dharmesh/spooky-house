# Turning the 2D art into 3D models

How to get reusable 3D models (glTF `.glb` files) for Anisha's Spooky House. Models made this way work in the Godot 3D
game and in any other engine (Unity, Unreal, Three.js, Blender).

> **Status:** route B is done for batch 1 below (31 objects, her shoes, Anisha and the scary teacher), generated by
> `npm run models` into `godot/assets/models/`. The remaining 150 objects are still plain boxes. See
> `godot/assets/models/MODELS.md`.

## Be clear about what Claude Design can do

**Claude Design draws pages and pictures. It does not export `.glb` 3D files.** What it is very good at here is the
**model sheet**: a clean, consistent set of front, side, back and top views of each thing, with sizes written on them. That
is exactly what a 3D modeller (or an image-to-3D tool) needs, and it keeps every model in the same style.

So there are three routes. They can be combined.

| Route | Who makes the `.glb` | Good for | Catch |
| --- | --- | --- | --- |
| **A. Model sheets, then a 3D tool** | Claude Design draws the sheets. Then Blender (by hand or with Claude writing the Blender script), or an image-to-3D service, makes the model | Characters and anything that must look like Anisha's drawings | Needs a 3D step outside Claude Design. Image-to-3D services have their own prices and licence terms; check the licence allows games |
| **B. Generated in code** | Claude Code writes a script that builds low-poly `.glb` files straight from the object list, with no drawing | All 184 objects quickly, consistent size, ready to use | Simple stylised shapes (boxes, cylinders, rounded blocks), not detailed art |
| **C. Browser exporter page** | A page (not the Design canvas) that builds the models in Three.js and has a **Download .glb** button | Previewing and tweaking models by eye, then saving | Same simple-shape limit as B |

**Suggested order:** B first (every object gets a decent low-poly model within the day), then A for the characters and the
few hero objects Anisha cares about most.

## The spec every model must follow

| Rule | Value |
| --- | --- |
| Format | glTF binary, `.glb` |
| Units | **1 unit = 1 metre.** 1 tile of the 2D art = 1 m |
| Footprint | Fills the object's tile footprint (a 4 × 2 sofa is 4 m × 2 m; keep ~4 cm clear on each side) |
| Origin | **Centre of the base**, sitting on the floor (y = 0) |
| Facing | The front of the object faces **+Z**. Models are rotated in-game from the room files |
| File name | The object id, e.g. `fridge.glb`, `sofa.glb`. Godot picks them up from `godot/assets/models/` by name |
| Size | Under 3,000 triangles per object (under 8,000 per character). The game runs in browsers and on phones |
| Look | **Granny's house objects:** black, grey and white only, spooky not cute. **Town objects** (little house, park, school, hospital, palace, pool): normal and bright, not spooky; real colours are likely but still to confirm with Anisha. Plain materials, no textures needed |
| Materials | 1 to 3 simple materials per object (e.g. body grey, edges lighter). No emission except lamps and screens |
| Pickups | Pickup items (cement bag, knife, remote...) should be easy to read at small size: chunky, slightly oversized |
| Safe look | Cartoon mischief only: no gore, no injury |

### Characters also need
- **Anisha:** about 1.2 m tall (child). Look still undecided, so first make a simple stand-in, then redo once Anisha decides.
- **Scary teacher:** about 1.6 m tall. Angry brows, frown (as in the 2D design).
- **Animations (named exactly):** `idle`, `walk`, `sneak` (crouched), `pickup`, `hide`. Baddies: `idle`, `walk`, `look_around`, `caught_you`. Looping animations loop cleanly.
- Rigged with a simple humanoid skeleton.

## Prompt A: give this to Claude Design (model sheets)

> Make a **3D model sheet canvas** for *Anisha's Spooky House*, a spooky top-down stealth-prank game for kids.
> Style: black, grey and white only (no other colours), spooky but not cute, no gore. Match the attached 2D
> objects' shapes and proportions exactly; do not redesign them.
>
> One artboard per object, all identical in layout (1,600 × 1,000):
> - **Four views, drawn orthographic and to the same scale:** front, side, back, top. Align the views on shared guide
>   lines so a modeller can read heights and widths straight across. Show the grid in 10 cm squares.
> - **Dimension lines** in metres on each view (width, depth, height), using these sizes: *[paste the row(s) from the batch
>   table]*. 1 tile = 1 metre.
> - A **material key**: 1 to 3 flat grey tones with names (for example "body", "edge", "handle").
> - A **three-quarter view** (45° from front-left, slightly above) shaded the way it should look in the game.
> - Notes in one short line each: what it is, which way is the front, anything that opens or moves.
> - Build the objects from simple shapes (rounded blocks, cylinders) and keep detail low-poly friendly: no tiny details a
>   3,000-triangle model could not hold.
> Start with these objects: *[paste the ids, e.g. fridge, counter, gas_stove, sink, table_dining, chair]*. Then characters
> as separate artboards: a **turnaround** (front, side, back, three-quarter) of *[Anisha / the scary teacher]* plus
> poses for idle, walk, sneak (crouched), pick up and hide. Keep every artboard's name equal to the object id.

For characters, repeat with the character's description and the 2D drawing attached.

## Check each model before using it

1. Size matches the table (it fits the footprint, and the height is right).
2. Origin is at the centre of the base: it sits exactly on the floor.
3. Front faces +Z.
4. Only grey and white materials, under the triangle limit.
5. Drop it in `godot/assets/models/` and look at it in the game: it should replace the box with nothing sticking out of
   the walls or floating.

## Using the models elsewhere

The same `.glb` files open in Blender, Unity, Unreal, Three.js and Phaser-with-Three.js with no conversion. Keep the
file names equal to the object ids so every game can find them the same way.
